# BB_RSI — change notes

Engine: `src/strategies/bb_rsi.js` · Routes: `bbRsi*.js` · Env prefix: `BB_RSI_*`

Append a dated bullet whenever this strategy changes. Newest on top.

## Log
- 2026-08-14: `BB_RSI_RESOLUTION` is back as a BB_RSI-only candle-size override — `global` (default, follows `TRADE_RESOLUTION`) / `3` / `5`, resolved once by `bbRsiStrategy.resolutionMin()` so Live/Paper/Backtest cannot drift apart; the 2026-08-07 global-only rule stands for every other strategy, this exists so 3-min can be tested without moving EMA_RSI_ST/PA/EMA9+VWAP too. Unrecognised values (incl. `15`) fall back to the global rather than NaN. `/all-backtest` still runs all panels at a fixed 5-min. Untested at 3-min, and switching also shortens every candle-counted rule (SL pause, opposite-candle stop/trail, confirmation candle) in proportion.
- 2026-08-14: **V8 — the engine is now MEAN REVERSION, the exact inverse of the V7 breakout.** CE is a fade of a drop (close ≤ BB lower + RSI ≤ 25), PE a fade of a rip (close ≥ BB upper + RSI ≥ 75); BB defaults move to 30 / 2. SuperTrend is deleted outright (it agreed with the breakout, so it vetoed every fade) along with the BB re-entry and trend-flip exits, `BB_RSI_SUPERTREND_*`, `BB_RSI_BB_REENTRY_*`, the chart line and the `supertrendAtEntry`/`stTrendAtEntry`/`trendSource` trade fields. New: middle-band target, a two-opposite-candle stop/trail (independent toggles, the trail arming at `BB_RSI_TRAIL_ARM_PTS`), band-width + RSI-range chop guards, an optional divergence gate that fails closed, `BB_RSI_ADX_MIN` → `BB_RSI_ADX_MAX` (the gate inverted — a fade dies in a strong trend), and `BB_RSI_CONFIRM_OUTSIDE_BAND` → `BB_RSI_CONFIRM_ON_CLOSE`. Entry SL line is the signal candle's own extreme. `signalStrength()` moved into the engine so the three routes cannot drift on an inverted comparison. The opposite-candle streak is capped at `position.candlesHeld` — without it the streak reached back through the entry and signal candles (both typically RED on a CE fade, being the tail of the sell-off being faded), so a 2-candle stop fired on the FIRST close after entry and killed trades that never got a bar to work. Every numeric config read goes through strict parsers that fall back to the documented default: a typo'd threshold was silently switching a chop guard OFF (a NaN makes every comparison false) or half-parsing (`"5o"` -> 5), and a malformed `HH:MM` removed the entry window entirely and traded the whole session. Explicit `0` still means off, but the structural inputs (periods, lookbacks, candle counts) carry a floor — unfloored, `BB_PERIOD=0` threw out of the Bollinger calc and a candle COUNT of 0 exited on the first close of every trade. **Not validated** — no paper session, backtest or replay has run against V8; `BB_RSI_MIN_BAND_WIDTH_PTS` and `BB_RSI_RSI_RANGE_MIN` are reasoned defaults, not measured ones.
- 2026-08-11: BB_RSI hard-SL no longer stacks. `cancelBbRsiHardSL` cleared the order id BEFORE the broker confirmed, so a failed cancel followed by the failed-exit re-arm could leave TWO SL-Ms resting on the same lot — both firing sells it twice, i.e. naked short. The id is now cleared only on a confirmed cancel, `placeBbRsiHardSL` refuses to place a second stop on the same contract, and a close that leaves an unconfirmed id retries the cancel then Telegrams.
- 2026-08-11: BB_RSI hard-SL trigger is now priced off the CURRENT spot (`state.lastTickPrice`) instead of `spotAtEntry` — the premium used is always current, so the entry-spot pairing was only correct while spot had not moved, and was materially off on the failed-exit re-arm path.
- 2026-08-11: BB_RSI LIVE order safety. The hard SL-M was placed for REAL even in dry-run (entry BUY simulated, SL-M sell sent to Fyers — a naked short if it triggered); it is now simulated with the entry. Real orders now require the new `BB_RSI_LIVE_ENABLED=true` on top of `LIVE_HARNESS_DRY_RUN=false`, enforced centrally in `liveDryRun`. The dry-run decision is stamped on the position at entry so an exit can never be simulated on a real fill, a failed square-off re-arms the SL it cancelled, an SL that fails to place now raises a Telegram alert, and the status page carries a DRY-RUN / REAL-ORDERS badge.
- 2026-08-11: Backtest now runs the CANDLE-CLOSE BB re-entry exit (`bbRsiStrategy.bbReentryExit`) as well as the armed intra-bar band touch. Paper and Live have always had both — the close check has no arming guard, so a breakout that never extends `BB_RSI_BB_REENTRY_ARM_PTS` past the band but closes back inside it exits on paper while the backtest kept holding. Live also now applies the OI + price-buildup entry gate (`oiFilter`) that paper has always run, and samples futures OI on every candle close (fire-and-forget, so no await is added to the candle-close path).
- 2026-08-11: light-theme `.run-btn` colour on the Backtest page — the dark navy fill had no entry in the light skin's hex rewriter, so it stayed a dark-theme button on a light page. Now a solid blue button with a white label (5.2:1). Styling only.
- 2026-08-10: Live page no longer shows an "Option SL" tile. It rendered `entry premium × (1 − OPT_STOP_PCT)`, but that key is EMA_RSI_ST's — no BB_RSI exit (engine, paper or backtest) ever referenced the number, so the page was advertising a stop that could not fire. Display-only removal; exits are unchanged.
- 2026-08-09: the held option contract is now streamed on the shared Fyers websocket (new `src/utils/optionFeed.js`) instead of this engine fetching it with its own repeated `getQuotes` poll — the premium the exit rules read updates per tick rather than once per poll interval, and the REST call only fires when the stream is quiet. The poll loop stays, as both the fallback and what renews the subscription lease, so `OPTION_SOCKET_FEED_ENABLED=false` (or a feed whose ticks carry no resolvable symbol) restores the previous behaviour exactly.
- 2026-08-08: paper entries now report against the shared Fyers capital pool (`src/utils/capitalPool.js`). Entry is synchronous and the premium only lands on the first option poll, so `qty × PAPER_CAPITAL_EST_PREMIUM` is blocked up front and corrected to the real premium there; released with the net P&L on exit. Advisory only — an unfundable entry is still taken and raises the Real-Time dashboard alert.
- 2026-08-07: Backtest "Run Again" no longer forces 5-min — the hidden resolution input now carries the run's actual resolution (digits-only, so the `?resolution=` query param can't break out of the attribute).
- 2026-08-07: Candle timeframe is now global — `BB_RSI_RESOLUTION` removed from Live/Paper/Backtest and Settings; all three read `TRADE_RESOLUTION` (Settings → Instrument & Backtest), same as every other strategy.
- 2026-08-06: Paper page no longer resurrects a PREVIOUS day's session on a trading day — the boot rehydrate's "last saved session" fallback (and the chart backfill that follows its trades' day) is now cleared unless today is a weekend/NSE holiday, so a restart with no trades yet shows today's empty session instead of yesterday's trades over yesterday's chart (new `src/utils/staleSessionGate.js`).
