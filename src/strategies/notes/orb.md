# ORB — change notes

Engine: `src/strategies/orb_breakout.js`, `src/strategies/orbExits.js` · Routes: `orb*.js` · Env prefix: `ORB_*`

Append a dated bullet whenever this strategy changes. Newest on top.

## Log
- 2026-08-13: **re-entry after a stop-out** (`ORB_REENTRY_AFTER_SL`, ships **0/off**) plus `ORB_ENTRY_START`, both from an owner review of the Jul–Aug 2026 export. Re-entry exists because raising `ORB_MAX_DAILY_TRADES` alone could **never** produce a second entry — the engine kept re-finding the day's one committed breakout candle and refused to enter late — so 2026-08-03 (CE stopped 10:35 on a 24pt breakout-bar stop, day then traded higher into 12:35) and 2026-07-29 (CE stopped 09:55, broke out again minutes later) were both un-tradeable by construction. New `orb_breakout.reentryPlan()` owns the rule and is called by paper, live, the backtest route **and** `scripts/lib/orbSim` (so a sweep measures the shipped rule); `orbExits.isStopOutExit()` owns which exits qualify — only hard SL / rupee cap / premium stop, never the EMA trail, opposite candle or EOD, because those mean the *move* ended rather than the breakout being wrong. On a stop-out `getSignal(..., {rearmAfterTime})` makes every candle **up to and including the stop bar** invisible to the breakout hunt, so only a genuinely fresh close beyond the same frozen edge re-enters, tagged `[re-entry]`. Proven on a synthetic session shaped like those two days: entry 09:35 → stop 09:40 → re-entry on the 09:55 confirmation of a new 09:50 breakout, with a new stop anchored to the new bar. `ORB_ENTRY_START` is the mirror of `ORB_ENTRY_END` (defaults to the OR freeze = no behaviour change) and exists to test "skip the 09:35 entries" — **the sample says don't**: pre-09:50 entries net −₹2,372 over 9 trades vs −₹4,213 over 8 after, and a delay deletes both of the sample's best trades. Also corrected a stale README claim that `ORB_SL_ATR_MULT` is inert — true only while `ORB_MAX_TRADE_LOSS` clamped the stop, and that now ships at 0. ORB suite 44/44.
- 2026-08-13: the ORB backtest can now price the SAME trades as **futures** — `INSTRUMENT=NIFTY_FUTURES` switches `runOrbBacktest` to index points × lot with futures charges and no δ/θ. Reason: across 821 trades the option wrapper (0.55 delta, theta, premium-wide spread) costs ~₹420 a round trip against an average trade of −₹300, so "is the breakout worthless, or is it the option wrapper?" could not be answered. Every ORB exit is spot-based except the premium disaster stop, which is skipped in this mode, so the two runs are comparable trade-for-trade. Option mode remains the default and is byte-unchanged (ORB suite 37/37). Context: four rule sets have now been measured on 2021→2026 — original (−₹190k), simplified (−₹237.5k, PF 0.66), +RSI/SuperTrend, and +1.5×ATR stop floor (−₹272.5k, PF 0.64, 29% WR). Widening the stop raised the win rate 27%→29% and made net WORSE, which is the signature of no edge: every knob moves win rate and loss size by the same amount in opposite directions.
- 2026-08-13: two momentum gates added to entry, both ON by default with their own toggles (owner request). **RSI** (`ORB_RSI_ENABLED`, period 14): CE needs RSI ≥ `ORB_RSI_CE_MIN` (51), PE needs RSI ≤ `ORB_RSI_PE_MAX` (49). **SuperTrend** (`ORB_ST_ENABLED`, `ORB_ST_PERIOD` 10 / `ORB_ST_MULT` 3) via the shared `utils/supertrend.js` — CE only when the line is below price, PE only when above. Both read the **entry** candle, the only bar whose momentum is knowable when the order goes in, on the same multi-day series the EMA trail uses; both fail OPEN during warm-up. They live inside `_fire`, so the confirmation, resume and retest paths all obey them. `ORB_RSI_PERIOD` / `ORB_RSI_CE_MIN` / `ORB_RSI_PE_MAX` were in `RETIRED_ORB_KEYS` and in README's bulk-delete block — removed from both (41 dead keys, not 44) so a `.env` clean-up cannot silently disable the rule. Verified on synthetic series: raising the CE floor to 99 blocks a 96.09-RSI entry, a PE against a still-bullish SuperTrend is refused, and each toggle restores the entry. `sig.rsi` / `sig.superTrend` / `sig.superTrendDir` now ride on every trade record.
- 2026-08-13: local `~/trading-data/backtest_cache` was auto-pruned mid-session, so the Mar–Apr 2026 candles used for every measurement above are gone from this machine. Any further ORB measurement has to run on EC2 (or re-fetch with a live Fyers token) — a local run now silently reports **0 trades**, which is missing data, not a strategy result.
- 2026-08-13: **defaults flipped to the owner's simplified ruleset** (he asked for the gates removed, not toggled). Out of the box ORB is now: OR 09:15–09:30 → any candle CLOSING past the edge is the breakout (no buffer, no ATR body, no VWAP, no day-sanity) → the next candle just has to CLOSE beyond that candle's close → stop = the breakout candle's low/high → EMA9 trail exiting on ONE close through it. No breakeven, no opposite-candle exit, no premium band. Every gate still exists behind its env key; only the defaults moved, and README + Settings were re-synced to match. **Caveat kept in the header: `ORB_MAX_TRADE_LOSS=1500` still clamps that structural stop on most trades (~38pt), so the rupee cap, not the breakout candle, is usually the real stop — set it to 0 to change that.** Verified with every `ORB_*` unset: 30 trades / 39 sessions, exits only `SL:12 trail:18` (no BE, no opp), matching the profile measured before the flip.
- 2026-08-13: **BUG FIX — a breakout-anchored stop could land on the wrong side of the entry.** With `ORB_SL_SOURCE=breakout` and `ORB_SL_ATR_MULT=0` (both now the defaults) the retest/resume path could enter *below* the bar the stop is anchored to: reproduced a CE entry at 150 with SL 175, i.e. an instantly-stopped-out trade. The ATR floor used to mask this — it cannot when the multiplier is 0. The stop now falls back to the entry candle's extreme, then to the opposite range edge, if the anchor is not strictly beyond the entry.
- 2026-08-13: **the entry stack is now fully switchable**, so "is this gate worth anything?" is a measurement instead of an argument. Five keys, every default = today's behaviour: `ORB_VWAP_FILTER_ENABLED` (true), `ORB_BUFFER_ATR_MULT` (0.3) + `ORB_BUFFER_MIN_PTS` (1) alongside the existing `ORB_BUFFER_OR_MULT`, `ORB_CONFIRM_MODE` (`extend`|`close`) and `ORB_SL_SOURCE` (`entry`|`breakout`). `ORB_BUFFER_ATR_MULT` and `ORB_VWAP_FILTER_ENABLED` were in `RETIRED_ORB_KEYS` — both removed from that list and from README's bulk-delete block (44 dead keys now, not 46), because deleting a live key from `.env` would silently change the strategy. **VWAP is measured worthless**: turning it off changed 0 of 36 trades on Mar–Apr 2026, the third independent test to say so — a close past the range edge before noon is essentially always the right side of VWAP. The user's simplified ruleset (no ATR body, no VWAP, no day sanity, no buffer, confirmation = "next candle closes beyond the breakout candle's close", SL = breakout candle extreme, EMA9 trail exiting on ONE close) runs as a pure config: on the 39 cached sessions it doubles trades (30 vs 15) and loses ₹10.3k against +₹3.2k — but that is 30 trades and decides nothing. The verdict needs the 2021→2026 backtest.
- 2026-08-13: two new **exit** dials, both defaulting to today's exact behaviour, plus seven sweep variants to decide them. Diagnosis from the user's own 2025 (n=123, 23% WR, −₹52,388, PF 0.51) and 2026 (n=60, 20% WR, −₹33,042, PF 0.38) backtest exports: at its avg win/loss ORB needs a **~40% win rate to break even** and gets 20%, gross profit is three trades (11 Mar +₹7,311 / 29 Apr +₹3,998 / 8 Jan +₹3,472 ≈ 75% of 2026's winnings), and the loss mass is a long tail of −₹200…−₹1,200 **EMA-trail** exits that each also pay ~₹420 of spread + theta. Entry is the confirmation candle's *close*, so price is already extended and the next candle often pulls back through an EMA still sitting under the entry. **`ORB_TRAIL_ARM_PTS`** (default `0`) blocks the trail from exiting until the trade is that far in profit — hard stop and ₹ cap still live. **`ORB_TRAIL_CONFIRM_CLOSES`** (default `1`) needs N closes in a row through the EMA. `emaBreaks` is deliberately outside the crash-recovery snapshot, so a reloaded position needs a fresh run of closes (errs towards holding). Both are HYPOTHESES: `scripts/orbSweep.js` gained `trail arms at +15/+25/+40pt`, `trail needs 2 closes` and three combinations, and the defaults do not move until one clears TRAIN **and** TEST on the full 2024→2026 run. The local Mar–Apr cache (10 TRAIN / 5 TEST trades) is far too small to decide — it only proves the levers bind (`2 closes` moved TRAIN −₹3,473 → +₹791).
- 2026-08-13: two new entry dials, both defaulting to today's exact behaviour. **`ORB_BODY_OR_CAP`** (default `0` = off) caps the decisiveness threshold at a share of *today's* opening range: `ATR5` is frozen from the previous days, so after a violent session it demanded a body larger than today's whole range — 2026-08-06 wanted 22.2pt against a 38.95pt range (57% of it in one candle), which no breakout can satisfy. It is a ceiling, so it can only let more breakouts through; unseeded `ATR5` still fails open. Verified on a synthetic 6-Aug-shaped session: dead at `0`, `BUY_CE` at `0.25`. **`ORB_BUFFER_OR_MULT`** (default `0.15`, unchanged) promotes the old hard-coded buffer constant so it could be measured — and the measurement says leave it: `0.10` / `0.05` bought 1–2 trades and took PF 0.93 → 0.64 / 0.59 (fake breakouts). Frequency sweep on the 39 cached sessions at production settings: baseline 15 trades / 38% of days / PF 0.93; the OR/ATR15 gate is the biggest frequency lever (→ 23–24 trades) but nets worse; everything loosened at once reaches 28 trades / 72% of days at −₹1,389 / PF 0.95. The body cap is a **no-op on that sample** (Mar–Apr ORs were wide, so `0.6×ATR5` already sat under any cap) — it only binds in the current quiet-open regime, so it ships OFF and is flipped in Settings. Skip-log and trace now name whichever rule set the threshold (`0.25×OR cap` vs `0.6×ATR5`).
- 2026-08-13: measured the **plain textbook ORB** (close beyond ORH/ORL, no buffer / body test / next-candle confirmation, stop at the opposite OR edge, 1×OR target) against the shipped engine on the same 39 cached sessions (Mar–Apr 2026, 09:30–11:50, same cost model). It trades 2.4× more often (36 vs 15) and its 61% win rate is bought with a **median 154.8pt stop ≈ ₹5.5k risk/trade**: raw net **−₹20,782** (PF 0.76). Clamp that stop to the shipped ₹1,500 budget and the win rate collapses 61%→36% for **−₹1,423** (PF 0.97) — the stop lands inside the noise. A VWAP filter on the breakout close removed **0 of 36** trades (a close beyond the edge before 11:50 is essentially always on the right side of session VWAP), so it is not a fake-breakout filter here. Conclusion: our add-ons are not what killed ORB — the textbook version is no better, consistent with the 329-trade no-edge verdict below. No code changed; throwaway script, not shipped.
- 2026-08-11: strategy guide re-headlined to the 329-trade verdict — the intro box and Section 10 led with the old 39-session "+₹3,415 / PF 1.44" figures and the "most promising idea" was still the OR-width cap, both of which the long sample falsifies; the settings-table row for `ORB_OR_MAX_PTS` now says stay off.
- 2026-08-11: **VERDICT — ORB has no edge; do not trade it.** Full backtest 2024-01-01 → 2026-08-11: 329 trades, 20.7% WR, net **−₹1,78,963**, PF 0.39, max DD −₹1.79L, Sharpe −5.44, and all three years negative alone (2024 −95.3k/PF 0.30, 2025 −51.4k/PF 0.52, 2026 Jan–Jul −32.3k/PF 0.38). That is past the ~147-trade power requirement, so it is a conclusion, not noise. The OR-width filter added earlier today fit 2025+2026 (OR≤70pt +10.6k/−3.4k vs OR>70pt −62k/−28.9k) and then **reversed on 2024** (OR≤70pt PF 0.24 vs OR>70pt PF 0.35) — fitted, not real. `ORB_OR_MAX_PTS` stays OFF and its comment now records the falsification. Next ORB idea must clear zero out-of-sample in `scripts/orbSweep.js` before it is written into the engine.
- 2026-08-11: doc sync for `ORB_OR_MAX_PTS` — the backtest page's notes line now names the cap when it is enabled (it listed the other day-sanity gates but not this one), and the strategy guide's Section 10 replaces "the most promising *untested* idea" with the 181-trade result plus the `orbSweep` command; settings table row added.
- 2026-08-11: new `scripts/orbSweep.js` runs a short list of named config hypotheses through the same simulation `orbValidate` publishes (day loop + cost model + stats extracted to `scripts/lib/orbSim.js`, `orbValidate` output verified byte-identical on Mar–Apr 2026) and forces a TRAIN/TEST date split, because every ORB filter tightened so far improves in-sample purely by dropping scratch trades. Added `ORB_OR_MAX_PTS` (absolute OR-width cap, default 0 = OFF) as the one lever with cross-year support: on the 2025 (n=122) and 2026 (n=59) backtests, OR ≤ 70pt was +₹10.6k / −₹3.4k while OR > 70pt was −₹62k / −₹28.9k at ~14% win. Verdict on those 181 trades: ORB is **not profitable** (−₹51.4k and −₹32.3k, PF 0.52 / 0.38) and the OR cap only takes it to break-even, so nothing was turned on.
- 2026-08-11: doc sync for the rescan — the strategy guide's entry gates 5/6 said a failed decisiveness check ends the day (no longer true) and the backtest page's notes line described the old first-close-then-judge order; both now match the engine, and `ORB_BREAKOUT_RESCAN` is listed in the guide's config table.
- 2026-08-11: follow-up to the rescan below — the skip-log funnel keeps its full trail on a rejected poke (`breakout:P,candle colour:P,decisive body:F`, first failure only, as before) instead of collapsing to `breakout:F`, and the candidate VWAP is now computed only after colour+body pass, so scanning every in-window candle costs the bar-based harnesses nothing.
- 2026-08-11: the breakout scan no longer locks onto the first close beyond the OR edge — a candidate that fails colour / body / VWAP is skipped and the hunt continues (`ORB_BREAKOUT_RESCAN`, default ON, `false` restores first-close-is-final). Trigger: 2026-08-11 a 7.8pt body at 09:50 vs a 19.1pt threshold killed a session that then fell ~135pt from the ORH. Quality now rides on the candidate itself (`_breakoutQuality`), so selection is still judged on data available at that candle's close — no repaint — and the skip-log wording says "hunting" instead of "no trade today" while the day is still alive.
- 2026-08-11: ORB hard-SL no longer stacks. `cancelOrbHardSL` cleared the order id BEFORE the broker confirmed, so a failed cancel followed by the failed-exit re-arm could leave TWO SL-Ms resting on the same lot — both firing sells it twice, i.e. naked short. The id is now cleared only on a confirmed cancel, `placeOrbHardSL` refuses a second stop on the same contract, and a successful exit that leaves an unconfirmed id retries the cancel then Telegrams.
- 2026-08-11: ORB hard-SL trigger is now priced off the CURRENT spot (`state.lastTickPrice`), not `entrySpot` — the premium in the formula is always current, so pairing it with the entry spot was only right while spot had not moved and produced a materially too-loose stop on the failed-exit re-arm path. The re-arm now reports whether a stop was actually placed instead of always claiming it was.
- 2026-08-11: ORB LIVE now places an exchange-resident SL-M on entry (`HARD_SL_ENABLED`, trigger = optionLtp − |spot − slSpot| × `HARD_SL_DELTA`) — it was the only live engine whose every stop lived in-process, so a crash / restart / PM2 reload mid-position left a real position unprotected. The trigger is re-priced when the stop trails (breakeven → EMA trail) and cancelled BEFORE the square-off SELL, awaiting an in-flight placement first so a resting SL-M can't be orphaned onto a closed position. A failed exit re-arms it. The dry-run decision is now stamped on the position at entry, so flipping the kill-switch mid-trade can no longer simulate the exit of a real fill.
- 2026-08-11: the backtest's risk-throttle ledger now records EVERY walked day, seeding 0 before the short-day / expiry-only skips. `orbPaper.recordDay(..., sessionPnl)` runs on every /stop, so a no-trade day lands as 0 and `evaluate` breaks the losing streak on it; recording only days that traded let a streak run across quiet days and sat the backtest out far longer than paper.
- 2026-08-11: Backtest now models paper's `ORB_MAX_DAILY_LOSS` kill and its risk throttle (consecutive losing DAYS / weekly loss), the latter through the same pure `orbRiskState.evaluate` the live path calls, fed by the backtest's own day ledger. `ORB_RISK_THROTTLE_ENABLED` defaults ON, so the backtest was previously trading through streaks and weeks paper had already shut down. The `ORB_VIX_ENABLED` gate is applied too, after the signal, exactly where paper runs it.
- 2026-08-09: the held option contract is now streamed on the shared Fyers websocket (new `src/utils/optionFeed.js`) instead of this engine fetching it with its own repeated `getQuotes` poll — the premium the exit rules read updates per tick rather than once per poll interval, and the REST call only fires when the stream is quiet. The poll loop stays, as both the fallback and what renews the subscription lease, so `OPTION_SOCKET_FEED_ENABLED=false` (or a feed whose ticks carry no resolvable symbol) restores the previous behaviour exactly.
- 2026-08-08: paper entries now report against the shared Fyers capital pool (`src/utils/capitalPool.js`) — the exact `qty × option LTP` is blocked on entry and released with the net P&L on exit. Advisory only: an entry the pool cannot fund is still taken and raises the Real-Time dashboard alert instead of being skipped.
- 2026-08-06: Paper page no longer resurrects a PREVIOUS day's session on a trading day — the boot rehydrate's "last saved session" fallback (and the chart backfill that follows its trades' day) is now cleared unless today is a weekend/NSE holiday, so a restart with no trades yet shows today's empty session instead of yesterday's trades over yesterday's chart (new `src/utils/staleSessionGate.js`).
- 2026-08-05: fixed the ORH/ORL overlay lines vanishing on the Paper/Replay/Live charts — they were anchored at candles[0] (7-day warm-up buffer) so the client's trim-to-today filter dropped the first point and collapsed each line to a single invisible point; now anchored to the first candle of the latest trading day (orbPaper.js, orbLive.js; Replay inherits Paper's chart-data).
- 2026-08-05: backtest hard-SL now delegates the DECISION to the shared exit engine's `orbExits.isHardSlHit` predicate instead of an inline `c.low<=sl`/`c.high>=sl` compare (fill stays local); removes latent drift if isHardSlHit ever changes. No behaviour change today.
